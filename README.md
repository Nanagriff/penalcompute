# Sentence computation

Ghana Prisons Service sentence computation: a reference engine in Python,
a shipped engine in TypeScript, and the JSON vectors that prove they agree.
The build plan and its standing rules are in the specification this
repository was built from; the rule set is `reference/RULES.md`.

```
reference/   Python 3, stdlib only. The specification. Never shipped.
vectors/     booklet.json, generated by Python, consumed by the TypeScript tests.
web/         Vite + React + TypeScript. src/engine/ is the port and imports nothing.
api/         FastAPI and SQLite. Receives reviewer disagreements and usage counts,
             and serves the private admin page at /admin (admin.py, admin_ui/).
deploy/      nginx, systemd, one-command deploy script, first-time setup notes.
```

## Check everything

```sh
cd reference && python3 test_booklet.py            # every booklet example, 0 failed
cd reference && python3 export_vectors.py --verify # vectors match the engine and regenerate byte for byte
cd web && npm install && npm test                  # every vector and unit test against the TypeScript port
cd api && ./venv/bin/python test_api.py            # feedback, usage and admin (needs: python3 -m venv venv, pip install -r requirements.txt)
```

## Run and build

```sh
cd web && npm run dev            # local, with /feedback, /usage and /admin proxied to uvicorn on 127.0.0.1:8001
cd web && npm run build          # PWA build in web/dist, precached, installable, with version.json
cd web && npm run build:single   # one self-contained HTML file in web/dist-single (feedback and usage counting compiled out)
cd api && ./venv/bin/uvicorn main:app --host 127.0.0.1 --port 8001
```

## The admin page

`/admin` shows how the tool is used and every reviewer report, behind one
shared password. Each report is set beside what the engine gave at the time,
what the reviewer gave, and what the reference engine gives now, and carries
a status: open, engine was right, reviewer was right, or fixed.

To try it locally, set a password and start the API from `api/`:

```sh
echo 'a password of your own' | ./venv/bin/python admin.py set-password
COMPUTATION_ORIGIN=http://127.0.0.1:4173 ./venv/bin/uvicorn main:app --host 127.0.0.1 --port 8001
cd ../web && npm run build && npx vite preview    # then open http://127.0.0.1:4173/admin
```

On the live site the password is set with `deploy/set-admin-password.sh`;
see `deploy/README.md`.

Usage counts hold the kind of computation, the time, the version, whether
the app was installed and whether the device was offline, with a random id
made in the browser to tell one device from another. They hold no date, no
sentence and nothing typed: the endpoint has no field for one and refuses
any it does not know.

## Adding a vector

Add the case to `build_cases()` in `reference/export_vectors.py`, run the
exporter, commit the regenerated `vectors/booklet.json`. Never edit the JSON
by hand: `--verify` will refuse it, and so will the deploy script.

Reviewer disagreements come out of the feedback database with
`api/to_vectors.py` and go into `vectors/reviewer.json`, where the Vitest
suite picks them up as cases that fail until settled.

## Standing rules, in short

The engine directory imports nothing, never touches `Date` outside
`holidays.ts`, uses integers only, carries the rule IDs from `RULES.md` in
its comments, reproduces the register layout exactly, flags every
ambiguity rather than resolving it, and holds no prisoner data anywhere.
